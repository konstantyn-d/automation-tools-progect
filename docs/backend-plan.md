# LoopCasts: план бэкенда и автоматизаций

Принцип: для каждой проблемы выбираем самый простой надёжный инструмент, а не «всё в n8n».
Иногда лучшая автоматизация вообще не процесс, а правильная структура данных (например, доступ, который сам заканчивается по дате).

Единственное жёсткое ограничение из PDF курса: **одна полная цепочка в n8n** (триггер, ≥2 интеграции, обработка ошибок, без секретов в workflow) и **один AI-компонент**. Поэтому цепочка «Заказ → Счёт → Оплата → Доступ» живёт в n8n, остальное там, где это оптимально.

## 1. Архитектура

```
Браузер (React, уже есть)
   │  /api/...
   ▼
API (Node.js + Fastify)  ←→  PostgreSQL  (одна база для всего)
   │ событие "order.created"             ▲
   ▼                                     │
n8n (цепочка заказа, сверка оплат, напоминания, AI-триаж поддержки)
   │
   ├─ VIES API (проверка VAT)            интеграция 1
   ├─ SMTP (письма; локально Mailpit)    интеграция 2
   ├─ банк (CSV KBC → позже API банка)   интеграция 3
   └─ LLM API (AI-триаж)                 AI-компонент
```

Локально всё поднимается одной командой `docker compose up`: Postgres, n8n, Mailpit (ловит все письма, ничего не уходит наружу), API. Аккаунты в облачных сервисах на этом этапе не нужны.

Почему так:
- **PostgreSQL вместо Excel-файлов и MySQL с MD5.** Одна база вместо 5 таблиц с цветами. Номера счетов выдаёт база внутри транзакции, поэтому дубли и дыры невозможны физически.
- **Свой API на Node (Fastify)**, а не всё через n8n. Вход, пароли, кабинет должны отвечать за миллисекунды и быть безопасными, это не работа для workflow-движка. Тот же язык (JavaScript), что и фронтенд.
- **n8n** для процессов «событие → несколько систем → решение → действие», где важно видеть шаги и ошибки, и где нетехнический человек может поменять текст письма или правило.
- Альтернатива, которую я отклонил: Supabase (готовые auth и база в облаке). Быстрее старт, но нужен аккаунт, привязка к вендору и меньше понимания, что происходит. Можно перейти позже, база та же (Postgres).

## 2. Каждая проблема → инструмент

| Проблема (из анализа) | Решение | Где живёт | Почему именно так |
|---|---|---|---|
| P1 Заказы письмом, неполные | Форма на сайте с обязательными полями + живая проверка VAT | API + фронтенд | Неполный заказ просто нельзя отправить |
| P1 Проверка VAT | VIES REST API (бесплатно, без ключа) | API (живая проверка) + n8n (финальная, с сохранением ответа) | Клиент видит ошибку сразу, а в цепочке остаётся доказательство проверки |
| P2 Дубли и дыры в номерах | Счётчик в Postgres с блокировкой строки в той же транзакции | База | Последовательности (sequence) дают дыры при откате, счётчик с блокировкой нет |
| P2 Ошибки НДС | Функция правил НДС (BE 21%, ЕС частные 21%, ЕС компании с валидным VAT 0% + reverse charge, вне ЕС 0%) | API, вызывается из n8n | Правило одно и протестировано, а не калькулятор в телефоне |
| P2 Счёт в Word | PDF генерируется из данных счёта (pdfkit) | API | Один шаблон, тот же PDF в письме и в кабинете |
| P2 ~210 ежемесячных счетов | Расписание 1-го числа вызывает ту же под-цепочку счёта | n8n | Переиспользуем уже готовые шаги |
| P3 Сверка оплат | Импорт выписки → сопоставление: структурированное сообщение (OGM) → номер счёта в тексте → сумма + имя → сомнительные человеку | n8n (расписание) + SQL-функция сопоставления | OGM убирает «детектив» почти полностью, а правила проще и надёжнее AI |
| P4 Доступ только в пятницу | Оплата найдена → аккаунт создаётся автоматически → письмо со ссылкой задать пароль | n8n → API | Доступ в тот же день |
| P5 Сброс пароля | Одноразовый токен по ссылке, хранится хешем, живёт 1 час | API | Классическая безопасная схема, n8n здесь не нужен |
| P12 MD5-пароли | bcrypt; старые аккаунты переносим, но заставляем задать новый пароль по ссылке | API + разовый скрипт | MD5 и пароли «имя+цифра» нельзя оставлять |
| P6/P7 Поддержка | Форма → тикет в базе → AI классифицирует и пишет черновик → человек одобряет | n8n (AI-компонент) + API | Текст свободный и двуязычный, правила по ключевым словам ломаются. Возвраты решает человек |
| P7 «Где мой счёт / доступ» | Кабинет: счета, статус оплаты, VAT/PO | API | Самообслуживание убирает ~30% писем без всякой автоматизации |
| P8 Зомби-аккаунты | Доступ = `end_date >= сегодня`, проверяется при каждом входе | База | Деактивацию нельзя забыть, если её не нужно делать |
| P8 Напоминания о продлении | Расписание: за 30 и 7 дней, ссылка «продлить в один клик» | n8n | Тексты писем меняет не программист |
| P5 напоминания о неоплате | Расписание 7/14/30 дней | n8n | Конец основной цепочки |
| P9 Рассылка | Сервис рассылок (Brevo): double opt-in, отписка, статистика из коробки | Brevo + API (форма) | Не пишем свой почтовый сервис, это решённая задача |
| P10/P11 Каталог | Курсы и видео в базе, импорт из `course catalogue.xlsx` и Vimeo-экспорта, страницы генерируются | База + API | Одна правда вместо Excel и 140 HTML |
| P10 Публичные видео | Ежедневная проверка privacy в Vimeo API, публичные сразу закрываются | n8n (позже, нужен токен Vimeo) | 3 видео сейчас открыты всем |
| O10 Поиск по видео | Транскрипты (Whisper) → полнотекстовый поиск Postgres + субтитры VTT | База + разовый пайплайн | Отдельный поисковый сервис не нужен для ~7 300 минут |
| P11/P12 Деплой, бэкапы | GitHub Actions (сборка/тесты), `pg_dump` по расписанию, uptime-мониторинг | GitHub + сервер | Инфраструктура, делаем в конце |

## 3. Порядок работы (каждый шаг: сначала объясняю, потом делаю)

1. **Инфраструктура + реальные данные.** docker compose (Postgres, n8n, Mailpit), схема базы, импорт и чистка реальных данных: продукты и цены из handbook, курсы из каталога, 599 видео из Vimeo-экспорта, клиенты из `users`, заказы и счета 2026, выписка KBC. Фронтенд переходит с моков на реальный каталог.
   Заодно исправлю моки: в реальности team licence = €599/год за 5 мест (не поштучно) и есть single course за €39.
2. **API: вход, сброс пароля, кабинет.** Перенос старых пользователей.
3. **n8n: заказ → VIES → счёт (номер, НДС, PDF) → письмо**, плюс error workflow.
4. **n8n: сверка оплат → аккаунт → письмо**, напоминания о неоплате.
5. **Продления и ежемесячные счета.**
6. **Поддержка с AI-триажем** (понадобится ключ API модели).
7. **Рассылка (Brevo), поиск по транскриптам, проверка privacy Vimeo** (понадобятся аккаунты/ключи).
8. **CI, бэкапы, мониторинг.**
